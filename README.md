# Antigravity Pipeline & Audit Skills

Набор профессиональных скиллов, правил и конфигураций субагентов для **Google Antigravity (AGY)**: Antigravity CLI (`agy`), Antigravity IDE и Antigravity 2.0.

> [!NOTE]
> Проект представляет собой глубокую адаптацию репозитория [Magerko/claude-code-skills](https://github.com/Magerko/claude-code-skills) под архитектуру харнесса Antigravity: поддержку Progressive Disclosure, нативную систему субагентов (`define_subagent` / `invoke_subagent`), изоляцию рабочих копий (`Workspace: branch/share`) и правила проекта `AGENTS.md`.

---

## Зачем это нужно

Работая с современными LLM-ассистентами, разработчики регулярно сталкиваются с тремя фундаментальными проблемами:
1. **Преждевременное кодирование:** Агент начинает писать реализацию раньше, чем согласованы требования, ограничения и контракты.
2. **Потеря контекста между сессиями:** Когда контекстное окно переполняется или начинается новая сессия, агент теряет нить рассуждений и требует повторного брифинга.
3. **Ложная уверенность («выглядит правильно»):** Ассистент рапортует об успешном выполнении задачи, основываясь на чтении собственного кода, а не на реальном запуске тестов и команд.

Этот репозиторий решает все три проблемы через **жёсткую дисциплину процесса**, **файловую фиксацию состояния на диске** и **независимый аудит изолированными субагентами**.

## Содержимое репозитория

### 1. `/pipeline` — проект от идеи до релиза (стадии 0–10)
Ведет разработку по 11 стадиям с непреложными шлюзами (gates):
```
0. context load    — подгрузка brief.md молча (без пересказа)
1. idea            — замысел, границы и цели (docs/pipeline/brief.md)
2. plan + criteria — проверяемые критерии приёмки DoD/AC (docs/pipeline/plan.md)
3. risk spikes     — разведочный код на выброс (docs/pipeline/spikes/)
4. contracts       — структуры данных, API, конфиги, ошибки (docs/pipeline/contracts.md)
5. vertical slice  — сквозной путь end-to-end с фактическим запуском
6. tasks           — атомарные задачи (1 задача = 1 коммит) (docs/pipeline/tasks.md)
7. implementation  — пошаговая реализация (по одной задаче за раз)
8. audit           — аудит свежим контекстом независимым субагентом (docs/pipeline/audit.md)
9. feedback        — перенос находок аудита в brief и лог решений (docs/pipeline/decisions.md)
10. release        — финальные проверки, доступы, бэкапы (docs/pipeline/release.md)
```
* **Шлюзы (Stop-the-line):** На выходе из каждой стадии агент материализует результат в `docs/pipeline/`, обновляет `state.md` и останавливается, спрашивая подтверждение у пользователя через `ask_question`.
* **Файлы, а не контекст:** Вся история и решения хранятся в репозитории проекта. Сессия может перезапускаться сколько угодно раз — состояние сохраняется в `docs/pipeline/state.md`.

### 2. `/launch-web` — аудит веб-сайта перед публикацией
* 52 пункта проверок в 8 категориях: обработка и доставка форм, индексация, `robots.txt`, мета/OpenGraph, доступность (a11y), скорость (Core Web Vitals), правовые страницы и согласие на обработку данных, аналитика, домен и резервные копии.
* **Принцип «проверяет, а не сочиняет»:** Агент никогда не выдумывает отзывы, адреса, телефоны или реквизиты бизнеса. Если данных нет, выставляется статус `🙋` («требуются данные от человека») и запрашивается конкретная информация.
* В каждом пункте описана **«Ловушка»** (например, 404 страница, отдающая HTTP 200, или `robots.txt` со стейджа, случайно закрывший прод от поисковиков).

### 3. `/launch-security` — аудит безопасности приложения
* 63 пункта в 12 секциях: секреты и токены, аутентификация и сессии, разграничение прав (IDOR, RLS), инъекции и XSS, валидация загрузки файлов, CORS и HTTP-заголовки безопасности, защита от брутфорса и лимиты расходов, утечки данных в логах и ответах API, аудит зависимостей, прод-гигиена, платежные вебхуки, безопасность внутренних LLM-вызовов.
* **Адаптация под стек:** В первую очередь определяет стек проекта (`package.json`, `requirements.txt`, `go.mod` и т.д.) и отсекает неприменимые пункты с пометкой `н/п`.
* **Протокол при утечке секретов:** Если найден действующий токен/ключ, агент немедленно прерывает аудит: **сначала отзыв и перевыпуск ключа у провайдера, и только потом очистка истории git!**

### 4. Субагенты для Antigravity (`agents/`)
* **`pipeline-auditor`**: Запускается на стадии 8 с моделью `pro` и отключенными правами на запись (`EnableWriteTools: false`). Проверяет критерии приемки реальным запуском тестов через `run_command`.
* **`pipeline-spike`**: Создает минимальный исследовательский скрипт в ветке `Workspace: "branch"`, запускает его и возвращает факты в `FINDINGS.md`.
* **`pipeline-task`**: Выполняет атомарную рутинную задачу в изолированной копии `Workspace: "share"`.

## Установка

### Вариант 1. Глобальная установка (рекомендуется)
Скиллы станут доступны во всех сессиях Antigravity CLI (`agy`) и Antigravity IDE на вашей машине.

#### Windows (PowerShell):
```powershell
.\install-antigravity.ps1
```
*(Для проверки без внесения изменений запустите `.\install-antigravity.ps1 -DryRun`)*

#### Linux / macOS (Bash):
```bash
chmod +x install-antigravity.sh
./install-antigravity.sh
```

Файлы копируются в каталог конфигурации пользователя:
* Скиллы: `~/.gemini/antigravity-cli/skills/`
* Правила: `~/.gemini/antigravity-cli/rules/AGENTS.md`

---

### Вариант 2. Локальная установка для конкретного проекта
Если вы хотите включить пайплайн только в одном репозитории и закоммитить его для всей команды:

#### Windows:
```powershell
.\install-antigravity.ps1 -Local
```

#### Linux / macOS:
```bash
./install-antigravity.sh --local
```

Скиллы установятся в папку `.agents/skills/`, а правила — в `.agents/rules/AGENTS.md` внутри текущего проекта.

## Как использовать

1. Откройте терминал с `agy` или чат в **Antigravity IDE / Antigravity 2.0**.
2. Используйте команды или естественные фразы:
   * **Запуск пайплайна:**
     ```text
     /pipeline
     ```
     или: *«Начнем разработку по нашему процессу»*, *«Запусти пайплайн со стадии 2»*.
   * **Предзапусковой аудит веб-сайта:**
     ```text
     /launch-web https://mysite.com all
     ```
     или: *«Проведи аудит сайта перед запуском»*.
   * **Аудит безопасности:**
     ```text
     /launch-security . auth,secrets,access
     ```
     или: *«Проверь приложение на уязвимости перед релизом»*.

3. **Отказ от остановок:**
   Если вы хотите пройти этапы без ручного подтверждения на каждом шаге, просто скажите:
   > «Не спрашивай, гони до конца»
   Пайплайн продолжит работу непрерывно, сохранив все артефакты на диск.

## Особенности архитектуры под Antigravity

1. **Progressive Disclosure:** В отличие от других харнессов, Antigravity не перегружает первичное контекстное окно. Полные инструкции скиллов и чеклисты из `references/` считываются моделью строго по мере необходимости.
2. **Песочница и изолированные воркспейсы:** Для задач стадий 3 и 7 субагенты запускаются с флагами `branch` и `share`, предотвращая загрязнение основной ветки кодом на выброс.
3. **Безопасность запуска команд:** Инструмент `run_command` в Antigravity позволяет выполнять тесты и сетевые проверки (`curl`) с контролем фоновых процессов и тайм-аутов.
